# 任务目标

实现 `codekit-ast-tree` 工具，并将其集成到 `vulcan-codekit` 技能组中。该工具用于对目录执行轻量级 AST 树索引，输出适合 AI 快速判断和二次精确获取的 Markdown 风格纯文本目录视图。

# 执行步骤

1. 梳理 `vulcan-codekit` 现有工具结构，复用 `codekit-ast` 的路径校验、文件收集和 AST 扫描能力。
2. 新增 `codekit-ast-tree` Lua 入口文件，实现目录扫描、顶级结构统计、文件总行数统计和紧凑 Markdown 文本拼装。
3. 在 `skill.json` 中注册新工具，并将缩写说明、适用场景和调用建议写入工具说明，而不是放进返回内容。
4. 使用仓库内可执行入口进行实际调用测试，重点验证：
   - 目录输入是否正常工作；
   - 返回内容是否为单一文本；
   - Rust 等静态语言是否能输出类型/impl/函数统计；
   - Lua 等动态语言是否避免输出不可靠的类级判断。
5. 根据测试结果微调输出格式，保证压缩率和可读性平衡。

# 技术选型

- 复用现有 `codekit-ast` 的 AST 能力与公共校验逻辑，避免重复实现和行为漂移。
- 返回格式采用 Markdown 风格纯文本，减少 JSON 转义和无效包装。
- 文件级摘要采用稳定缩写和单文件单行形式，尽量减少误解与额外 token 消耗。

# 验收标准

- `vulcan-codekit` 中成功注册 `codekit-ast-tree` 工具。
- 工具支持目录输入，并能输出多文件的紧凑文本树视图。
- 返回结果不混入冗余说明性字段，主要结果为可直接阅读的文本。
- 测试通过，输出格式适合 AI 后续据此选择文件做精确分析。

# 执行变更总结

## 1. 核心修复与调整概述

- 新增 `codekit-ast-tree` 工具，定位为“目录级 AST 导航入口”，专门用于首轮全盘筛选和文件定位。
- 工具返回值改为 Markdown 风格纯文本字符串，而不是 `content` 包裹表结构，减少额外包装层。
- 输出格式采用“按目录分组 + 单文件单行摘要”，并统一支持 `l/t/i/f/m` 紧凑指标。
- 通过真实 `--call-tools` 调用完成了 Rust 目录、Lua 目录递归以及显式文件误传场景验证。

## 3. 💻关键代码调整详情

- 复用了 `codekit-ast` 的路径校验、目录/文件收集、AST 扫描、符号归一化与建树逻辑，避免新工具与主工具行为漂移。
- 新工具限制为“仅接受目录输入”，若传入显式文件会直接返回结构化错误。
- 文件级摘要按以下规则压缩：
  - `l`：文件总行数
  - `t`：顶级类型级结构数量
  - `i`：顶级 impl/extension 风格结构数量
  - `f`：顶级自由函数数量
  - `m`：顶级类型或 impl 下的方法数量
- 对静态语言仅展示少量顶级 `impl/class/interface/struct/trait/protocol` 名称及行号范围；对 Lua 这类动态语言不强行输出不可靠的类级判断。
- 为避免依赖主工具闭包里不稳定的局部函数引用，在树工具内部补了本地 `format_line_span` 实现，保证行号范围格式稳定。

## 4. ⚠️遗留问题与注意事项

- 由于 `--call-tools` 调试模式最终仍会把返回值 JSON 序列化到 stdout，因此终端里看到的字符串仍会包含引号与 `\\n` 转义；这属于调试输出层表现，不是工具内部再次包了一层 `content`。
- 当前工具尚未加入长度限制或超限裁剪策略；如后续需要按客户端类型限制字符数，应在此基础上继续补充超限处理规则。
- 本次未改动 `codekit-ast`/`codekit-rg` 的正式详情输出逻辑，仅新增目录级筛选工具供后续联动使用。
