## 任务目标

为 MCP 宿主增加统一的临时目录清理机制，确保运行时产生的临时文件不会无限堆积。

本次目标要求：

1. MCP 临时目录按“文件最后修改时间”清理。
2. 超过 1 天的临时文件需要自动删除。
3. 在服务启动时执行一次清理。
4. 当服务跨天持续运行时，也要在日期变化后继续触发清理，确保超过 1 天的临时文件被清掉。

## 执行步骤

1. 梳理当前 `vulcan.temp_dir` 的生成与使用位置，确认最合适的宿主层清理接入点。
2. 在 Rust 宿主中实现通用的临时目录解析与清理逻辑，按文件修改时间删除超过 1 天的文件。
3. 增加“按天只执行一次”的守卫机制，避免每次请求都做全量清理。
4. 在服务启动路径与本地 `--call-tools` 调试路径上统一接入清理逻辑。
5. 补充必要的中文计划记录与说明，验证清理逻辑不会误删非临时文件。

## 技术选型

- 清理逻辑放在 Rust 宿主层，而不是 Lua 层，避免依赖某个具体 skill 才能触发。
- 使用文件系统的 `modified` 时间作为删除判断依据。
- 使用“当前日期键”做一次性清理节流：同一天只做一次，跨天后自动再次执行。
- 仅处理宿主约定的 temp 根目录及其子目录，不扩展到其他业务目录。

## 验收标准

1. MCP 启动时会自动扫描临时目录，并删除最后修改时间超过 1 天的文件。
2. 服务长时间运行跨天后，再次触发时会继续清理超过 1 天的临时文件。
3. 清理逻辑只作用于 MCP 临时目录，不影响其他目录。
4. 本地构建与验证通过。

## 执行变更总结

### 1. 核心修复与调整概述

- 在 Rust 宿主层新增统一的临时目录维护模块，负责解析运行时 `temp` 目录、清理超过 1 天的旧文件，并在跨日时做一次性补充清理。
- 启动路径与 `--call-tools` 本地调试路径均已接入启动清理，保证服务启动后就能回收过期临时文件。
- `vulcan.temp_dir` 的目录解析统一复用宿主层能力，避免 Lua 与 Rust 各自维护一套 temp 路径逻辑。
- 跨日判断已按本地日期实现，而不是按 UTC 天数计算，避免本地已经换日但后台未触发清理的问题。

### 2. 📂文件变更清单

#### 新增

- `src/temp_maintenance.rs`

#### 修改

- `src/main.rs`
- `src/lua_engine.rs`
- `Cargo.toml`

### 3. 💻关键代码调整详情

- 新增 `CleanupTrigger` 与 `maintain_runtime_temp_dir`，区分“启动强制清理”和“跨日按天清理”两种触发方式。
- 新增 `spawn_cross_day_cleanup_task`，以小时级轮询检查本地日期是否变化，并通过内存态 `last_cleanup_day_key` 保证同一天只执行一次跨日清理。
- 新增 `resolve_runtime_temp_dir` / `ensure_runtime_temp_dir`，统一 temp 根目录为“程序目录上级目录下的 `temp`”。
- 清理逻辑按文件 `modified` 时间判断，仅删除超过 24 小时的普通文件，并在递归过程中顺带移除空目录。
- `lua_engine` 中的 `vulcan.temp_dir` 改为直接使用宿主层统一解析结果，保证 Lua 侧落盘目录与宿主清理目录完全一致。

### 4. ⚠️遗留问题与注意事项

- 当前跨日清理采用小时轮询，因此在本地日期变化后的最长 1 小时内完成补充清理，这属于预期行为，不会在每次请求时重复扫描。
- 清理范围严格限定在运行时 `temp` 根目录下，不会扩散到业务工作目录或其他输出目录。
- 已验证启动清理场景：超过 1 天的旧文件会被删除，当天新文件会被保留。
