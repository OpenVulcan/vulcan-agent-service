## 任务目标

为 Lua skill 运行时引入多路负载能力，避免所有 Lua 调用共用单一虚拟机锁，支持：

1. Lua 虚拟机池
2. 新调用复用池内虚拟机
3. 根据负载动态新增虚拟机
4. 配置最小虚拟机数量
5. 配置最大虚拟机数量
6. 配置空闲多久后销毁多余虚拟机

## 执行步骤

1. 梳理当前 `LuaEngine` 的单虚拟机结构、全局锁范围，以及 skill 加载与调用链路。
2. 设计 Lua VM 池的数据结构与生命周期策略，明确：
   - 预热最小实例数
   - 按需扩容
   - 最大实例上限
   - 空闲回收
3. 扩展配置项，增加最小/最大 VM 数量与空闲回收时间。
4. 改造 `LuaEngine` 调用路径，使 skill 调用和 `run_lua` 走 VM 池复用，而不是单实例串行。
5. 完成构建与基本并发验证。
6. 记录执行变更总结并归档。

## 技术选型

- 保持 `LuaEngine` 作为对外门面，但内部切换为 VM 池管理。
- 单个 VM 内仍保持本地串行，跨 VM 实现并发。
- 默认预热少量 VM，避免冷启动过高；负载增长时按需扩容。
- 空闲回收仅回收到最小 VM 数量，不影响基础可用性。

## 验收标准

1. 存在可配置的 Lua VM 池
2. 支持最小/最大 VM 数与空闲销毁时间配置
3. 新 Lua 调用优先复用池内 VM，必要时可扩容
4. 空闲 VM 会按策略回收，但不会低于最小数量
5. `cargo build` 通过

## 执行变更总结

### 1. 核心修复与调整概述

- 将 `LuaEngine` 从单一 `Lua + Mutex` 结构改造为可配置的 Lua VM 池。
- 新增最小 VM 数、最大 VM 数、空闲回收时间三项配置，并在启动时注入。
- Lua 调用现在优先复用池内空闲 VM，池空且未达上限时会按需扩容。
- 空闲 VM 会在归还或借用时做机会式回收，但总量不会低于最小值。

### 3. 💻关键代码调整详情

- 在 `src/lua_engine.rs` 中新增：
  - `LuaVmPoolConfig`
  - `LuaVm`
  - `LuaVmPoolState`
  - `LuaVmPool`
  - `LuaVmLease`
- 将 `LuaEngine::new()` 改为接收池配置，并在 `load_from_dirs()` 完成技能加载后按最小实例数进行预热。
- 将 `call_skill()`、`run_lua()`、`run_skill_helper()` 改为从 VM 池借用实例执行，而不是共享单一全局 VM。
- 在 `src/config.rs` 中新增：
  - `lua_vm_pool_min_size`
  - `lua_vm_pool_max_size`
  - `lua_vm_pool_idle_ttl_secs`
- 在 `src/main.rs` 与 `src/server.rs` 中补齐配置传递链路。

### 4. ⚠️遗留问题与注意事项

- 当前空闲回收采用机会式策略，在借用/归还时触发，没有单独后台清理线程。
- 每个 VM 内部仍保持串行执行，但不同 VM 之间已经可以并发。
- 正式运行中的服务仍需重启，新的池化配置和并发行为才会生效。
